# booking-lookup

Custom **booking-lookup** block. Purpose: booking lookup form (booking reference or ticket number, first and last name) that validates in the browser and hands off to the live check-in app, with optional extra content tabs.

## Authoring (Document Authoring)

Model: `standalone`

Single block table. Content: 2 columns, label | value; every row optional. Tab | Booking reference or ticket number (first Tab row = the form tab; an optional Panel row right after it adds intro content above the form); Login notice | text + 'Go to login' link; Reference label | Booking reference or ticket number (DE: Buchungscode oder Ticketnummer); Reference pattern | ^([A-Z0-9]{6}|\d{13})$ (default; input is upper-cased and spaces removed before the check); First name label | First name (Vorname); Last name label | Last name (Nachname); Submit label | Confirm (Bestätigen); Submit URL | hand-off URL or pattern with {COUNTRY}, {LANG}, {REFERENCE}, {FIRSTNAME}, {LASTNAME} (default https://once.lufthansa.com/connect/main-app?APPID=LHG_ONLINE&COUNTRY={COUNTRY}&LANGUAGE={LANG}&TENANT=LH&MODE=PORTAL); Errors | First name is required, Last name is required (2 items = first/last name, 3 items = reference/first/last). Single error rows: Reference error, First name error (Vorname ist erforderlich), Last name error (Nachname ist erforderlich); Tabs label (accessible name of the tab bar: Find your booking / Buchung finden). Extra tabs: each further 'Tab | label' row followed by 'Panel | rich content' (paragraph, link, image) becomes a WAI-ARIA tab; without extra tabs no tab bar is drawn. Nothing is sent anywhere: submit validates and navigates to the Submit URL. Unknown rows are ignored. Sections right after the block's section with the section style `in-booking-lookup` are shown inside the form tab, below the form (live: "How to get your boarding pass" belongs to the first tab: hidden with the tour operator tab, before the second accordion row on mobile); the block must be the last element of its section for this.

## Behaviour

Tabs share the width equally (50/50 with two tabs); below 768px they become accordion rows (the form tab open). The submit button is as wide as its label from 768px.

Own-host hand-off (scripts/handoff.js, brief 207): on the airline's own www host (www.lufthansa.com; a brand's `www` in scripts/brands.js) the form does what www's AEM component does instead of opening the page on www (which would be this page again once www is this site): the check-in form (when its hand-off is on that host: ITA's Submit URL; lufthansa.com's check-in app on once.lufthansa.com stays as it is) posts `/service/secured/api/core/checkin/fktn` with X-Portal, X-Portal-Site, X-Portal-Language and JSON `{"firstName","lastName","fileKey","layout"}` (layout `S` below 768px, else `L`); the manage bookings search (variant my-bookings, booking code + last name) posts `/service/secured/api/core/filekeylogin` `{"filekey","lastname"}` and then calls `GET /service/secured/api/core/booking/bookingdetailslink?layout=L|S` (the login's session cookie). The answer's target (`targetURL`, `parameters` as `[{key, values}]`, `methodGet`, `newWindow`) opens as www opens it: a form with a field per value, POST unless methodGet, a new window if newWindow. A failure shows www's text of its error code (`common.checkin.error.<code>` of the page's common labels; built-in English and German copies) above the button. Every other host keeps the hand-off above (the test-data backend behind turnsthe.page never gets a visitor's booking data); `?handoff=post` turns the post mode on for a test on turnsthe.page and aem.page. The tour operator search keeps opening the live page.

## Supported variations

- `my-bookings`: the manage bookings tab (live dcep-quick-actions with only "My bookings", /de/en/book-and-manage/booking-services/manage-my-bookings). One tab with the my-bookings icon (an accordion row across the viewport below 768px that opens and closes), the Travel ID login link, Booking code and Last name, the checkbox "I have a tour operator code" (switches to Last name, First name, Tour operator trip code with its hint and info text), the yellow "Find Bookings" button. Rows (all optional, the importer writes the ones the snapshot shows): Tab | My bookings; Login link | link; Reference label | Booking code; Reference pattern | ^[A-Z0-9]{6}$; Reference error; Last name label; Last name error; Tour operator label; First name label; First name error; Tour operator code label; Tour operator code hint; Tour operator code error; Tour operator code info; Submit label. Defaults: the recorded live labels (quickactions, bookingQuery, tourOperatorQuery; English and German). Hand-off: the live tab logs in with booking code and last name and posts to the booking deeplink its service returns (tour operator: the Travel ID upcoming-trips API); neither can be called from the replica, so a valid search opens the same page on the site's www (www.lufthansa.com, a brand site's own www), with none of the entered data in the URL.
- `my-bookings checkin` (brief 445): SWISS's online check-in as www's: Booking code / ticket no. (13 characters, the Reference pattern row), First name and Last name, each with its hint under it when the row `First name hint` / `Last name hint` / `Reference hint` has one (the field's description; hidden while the field shows its error), no tour operator checkbox. Rows as `my-bookings` plus First name label, First name error and the hints; the hand-off as `my-bookings`.
- `booking-code` (brief 369): the login page's "Booking code" modal of Discover, Austrian, Brussels Airlines and SWISS (www's dcep-login-form in a maui-modal). The block renders a dialog only; the page's links to `#booking-code` (the login card's "Enter booking code" button) open it, and a page reached with `#booking-code` opens with it. Fields as www's: Booking code (6 capitals or digits, or a 13-digit ticket number; max 13) and Last name (www's letters pattern; max 31). Checked as www checks them: an error box above the fields (www's "2 errors have occurred. …" or its one-error headline, each message with "Go to error") and the message under each field. A valid entry ends as www's: a form posted in the same window to the brand's shop (`/booking/manage-booking/retrieve` with lang and portalCountry in the query; fields lang, portalCountry, lastName, recLoc; scripts/handoff.js `retrieveTarget`: Discover hands off to shop.lufthansa.com as its www; lang per page language, portalCountry the page's market). On the airline's own www host www's filekeylogin and bookingdetailslink come first (the post mode). Texts: www's label service per brand and language (`booking-code-texts.js`, from the capture of 2026-11-05); a row with a text's key (e.g. `Submit label | …`) overrides it. No rows needed. A brand without a shop table (ITA, whose www form sends nothing; lh-com) renders nothing.
