# poi-map

Custom **poi-map** block. Purpose: the live points-of-interest map (`.poimapping > .dcep-poi-mapping`): a 500px map with location pins, zoom buttons bottom right and a bubble per pin (title, optional "Visit website" link) on hover or keyboard focus.

## Authoring (Document Authoring)

Model: `standalone`. Rows (all optional, but without Source or point rows the block shows nothing):

| Row | Value |
| --- | --- |
| Source | the live component's JCR path (`/content/lh/markets/de/en/.../poimapping`, the decoded data-dcep id) or the base64 id itself; the points come from GET /service/api/pointsOfInterest/{id} |
| *Title* \| *Lat, Lng* \| *Link* | an authored point (3 cells: "Parc de la Ciutadella \| 41.3881, 2.1873 \| https://…"; link optional); when the block has point rows, they are the points and nothing is requested |
| Caption | rich text under the map (live: the text under the map in the same column, "For more information about our tips, please click on the points on the map above.") |
| Aside | rich content beside the map, two equal columns from 768px (live: the other column of the `.twocolumn` around the map, e.g. "Our recommendations" and its list) |
| Tiles | `osm` (default) or `carto` |

Label rows (override): Zoom in label, Zoom out label, Visit website label, Map label, Attribution label. Precedence: authored row, then labels/common (`common.sr.mapview.zoomIn`, `common.sr.mapview.zoomOut`, `common.misc.cms.visitWebsite`: "Zoom in", "Zoom out", "Visit website" / "Website besuchen"), then built-in English/German copies.

## Behaviour

- Points: authored point rows, else GET `/service/api/pointsOfInterest/{id}` (scripts/lh-api.js `pointsOfInterestRequest`, `mapPointsOfInterest`; `pointsOfInterest/` is a direct route of scripts/lh-data.js: called on www.lufthansa.com with the market's X-Portal-* headers and no cookies, the exact recording as fallback; "=" of the id is sent unencoded like the live apicase client, recordings match with "=" or "%3D"). Answer `{"pointsOfInterest":[{"lat","lng","title","link"?,"linkLabel"?,"linkExternal"?}]}`; points without valid coordinates are left out, one per position.
- No points (no answer, nothing recorded): the block is hidden (the live component then leaves an empty 500px box); with an Aside only the aside stays. `data-lh-source`: live / recorded / none for the points (labels/common in `data-lh-sources`), `authored` for point rows.
- Map: loaded when the block comes within 300px of the viewport. First view = the live `fitBounds` over all points (highest zoom at which all fit, 48px kept above for the pins, 24px elsewhere; a single point gets the tile source's maximum zoom, 19 for OSM, live shows zoom 20 there); zoom 2 … 19 with the buttons (40px squares, black 60 %, white plus / minus, 10px apart, 34px from the bottom, 20px from the right, sr-only labels); drag with mouse or pen to pan (touch scrolls the page; the buttons zoom).
- Pins: deep blue location pin (24px, tip on the point), focusable (`role=group`, `aria-label` = title). Hover or focus opens the bubble (white, 4px radius, soft shadow, at most 300px wide, its tip at 25 % of its width, the live `translate(-25%, -100%)`): title (LufthansaHead bold 20–24px) and, with a link, "Visit website" (or the point's linkLabel; 14px bold service link with ↗). With a link the whole bubble is the link and gets the focus (live), new tab when `linkExternal` or the link leaves lufthansa.com; Escape closes it. Opening one bubble closes the others; the map pans so an open bubble stays inside.
- Attribution "© OpenStreetMap contributors" (and "© CARTO") bottom right, as the tile licences require.

### Tiles: why not Google, and what differs

The live map is the Google Maps JavaScript API with Lufthansa's key (`common.servicing.default.googleMapsApiKey`, AIzaSyBt5V5k5u7EORTgOsHSMqhdCcAJKRPsgAg) and a custom StyledMapType (from 5e1bfdb4.chunk.js: geometry lightness 45, labels lightness 25, no POI, transit, country/province borders or road labels, roads simplified, arterials white with #ccc edge, highways #ffe8b2 with #ffad00 edge, water #d4e4f4). That key is restricted to lufthansa.com referrers, and using it elsewhere would break Google's terms, so the replica draws its own map: a hand-written Web Mercator tile grid (no library, no build step, ~10 KB) with OpenStreetMap's standard raster tiles (`https://tile.openstreetmap.org/{z}/{x}/{y}.png`, no key, attribution required, light use only: Lufthansa-scale traffic would need a paid or own tile server) softened with a CSS filter (desaturated, lighter) towards the live style; `Tiles | carto` uses CARTO's light OSM style (`https://basemaps.cartocdn.com/light_all/{z}/{x}/{y}.png`, closer to the live colours; free tier limits apply). A static map image was not chosen: it would lose the zoom, pan and pin bubbles. Cannot match live: Google's cartography and its exact styling (roads, label density, water colour), the Google logo and keyboard-shortcut help, zoom 20+ for single points, two-finger pan / ctrl+wheel zoom on the map.

## Import

Source: `.poimapping > .dcep-poi-mapping` (13 maps per market on 12 pages; /{cc}/{ll}/first-class has two, one in each tab), `data-dcep` `{"id": "<base64 of the component JCR path>"}`.

- Drop everything rendered inside `.dcep-poi-mapping` (Google's map as text: "Zoom inZoom out", the keyboard shortcut table "Nach rechts / Nach oben …", "Kurzbefehle", "Kartendaten ©2026 Google", the tile images with the API key, the "Loading..." text).
- Write one `poi-map` block where the component is, with `Source | {atob(id)}` (the decoded JCR path; the block re-encodes it, which gives exactly the live id for all 52 ids). No point rows (the titles exist only in the API answer).
- In a `.twocolumn` whose column holds the map (the explore-the-world articles: `…/twocolumn/col1/poimapping`): do not write a Columns block for that `.twocolumn`; write the poi-map block with `Caption | {the rest of the map's column (e.g. the paragraph under the map)}` and `Aside | {the other column's content}` (headings, the link paragraphs, keep the `{heading-small}` markers). Elsewhere (section, sidebar-content of the stopover pages, the first-class tab columns, explore-the-world overview) write just the block in the flow.
- Today's imports (e.g. content/de/en/articles/explore-the-world/a-perfect-day-barcelona-in-one-day) contain a `columns-media` with the caption in the first cell and the recommendations in the second: replace it by the poi-map block as above.
