# flight-search

Custom **flight-search** block. Purpose: flight search form (trip type, travellers, nonstop, origin/destination autocomplete, dates) that hands the search off to shop.lufthansa.com as a POST form navigation to `/booking/availability` (fields `lang`, `portalCountry`, `search` JSON; see `tools/importer/IMPORT-NOTES.md`, Shop handoff).

## Authoring (Document Authoring)

Model: `standalone`

Single block table. Content: 2 columns, label | value. Rows (all optional): Tabs | Flights; Trip types | Round trip, One way (first = round trip, second = one way; a missing second type gets the live one-way label); Default trip type | Round trip; Traveller label | Economy, 1 Traveller; Nonstop label | Nonstop only; From label | From; Default origin | Frankfurt (FRA) or FRA (omitted: the market default airport from /service/api/defaultAirport, like the live prefilled origin); Default destination | code; To label | To; Date label | Departure - Return (split at ' - ' into the two date labels); Date error | Please provide travel date(s); Submit label | Find flights; Where we fly | link; Cabin | E (E economy, P premium economy, B business, F first); Adults | 1. Overridable UI rows: Trip type label, Swap label, Departure label, Return label, One way date label, Return date error, Origin error, Destination error, Same airport error, No results label. UI strings: an authored row wins, then the live labels (/service/api/labels/flightmanager and common), then built-in English/German defaults. The importer does not write the From/To/Date/Submit label rows or the date error (the snapshots show the flight manager's built-in texts, e.g. "Search flights", "Departure - return"; the live site shows the labels: "Find flights", "Departure - Return"), and authors only the selected trip type when the dropdown is not rendered (the one-way option then gets the live label "One-way" / "Einfacher Flug").

Behaviour: a chosen airport shows its name only ("Frankfurt", like the live prefilled origin); a typed code without a name shows the code.

URL parameters (`url-prefill.js`, as www.lufthansa.com's flight manager): on load the block reads the page URL's query string and the part after `#` (both `key=value&...`, URL-decoded; the hash wins on a clash), fills the form and then takes exactly these parameters off the address bar (`history.replaceState`; every other parameter and hash stay). Names (case-sensitive, as www's): `OriginCode`, `DestinationCode` (three-letter airport or city codes, named like an authored code: from the airport names list, else afterwards from the airport suggestions (the code as the term, the matching entry's name as the field shows it once picked: "Munich", "New York - JFK International, NY"; www's names list holds Frankfurt only), one request per field after the form is shown, an unknown one shows the code; with `OriginCode` no defaultAirport request; a code outside the Airports row is ignored); `TripType` = `roundtrip` | `oneway` (`IsOneWay=true|false` the second spelling; one way hides the return date); `DepartureDate`, `ReturnDate` = `YYYY-MM-DD` (from today on; a return before the departure or on a one-way trip is dropped, no error on load); `PaxAdults`, `PaxYoungAdults`, `PaxChildren`, `PaxInfants` (into the picker within its limits: 1-9 adults, nine seats, an infant per adult; young adults only where the `Young adults` row is on for the root, else they count as adults, as www where the route has none); `Cabin` = `E`, `N` (www's premium economy, our `P`), `P`, `B`, `F` (ignored when the Cabins row doesn't offer it). Without the Passenger picker row the counts and cabin fill the traveller line ("First, 2 Travellers") and the hand-off. The URL wins over the authored rows and the market default airport; the rows stay the defaults for the rest. Without these parameters nothing changes. www's other names (PaxInfantsOnSeat/OnLap/WithSeat, PaxStatusesAdults/Children, AccessCode, ActiveTab, Duration, Month, Year, AirlineCode) have no field here and stay in the URL; www's origin from the visitor's recent search has no counterpart (none is kept here).

Tabs: the Tabs row lists the live flight manager's tabs (Flights / Flüge, Flug & Hotel, Rental car / Mietwagen, Hotel); the kind of a tab follows from its label. `Active tab | Hotel` selects a tab other than the first. In the standalone variant, or as soon as a tab other than Flights is listed, the block shows a tab bar (icon only below 768px): the Flights tab shows the flight search, the Hotel tab the hotel search, and every other tab (rental car, flight + hotel) opens the same page on www.lufthansa.com in a new tab. Without a flight tab no live flight data is loaded (`data-lh-source="none"`; only the hotel button label).

Hotel tab (Booking.com, /de/en/hotel-offers, the hotel tab on /de/en/cash-and-miles): Location (empty), Check-In (today) and Check-Out (tomorrow) with hints, footnote, "Search hotel" button and a close button (from 768px; it closes the tab content, a tab opens it again). Rows (all optional, the importer writes them from the rendered hotel tab): Location label, Location hint, Location error, Check-in label, Check-in hint, Check-in error, Check-out label, Check-out hint, Check-out error, Check-out order error, Hotel footnote, Hotel submit label, Hotel external note (the button's "external website" tooltip), Close label, Live page (link). Defaults: the live hotel tab's built-in English texts, which the live site shows in every market (German only for the tooltip and the close button). The button text comes from the live label bundle (`labels/flightmanager`, `flightmanager.hotel.default.searchButton`: "Hotelsuche" on de/de and at/de, "Search hotel" on de/en and gb/en), as the flight tab gets its labels, also without a flight tab; a Hotel submit label row other than "Search hotel" wins. Handoff: the live tab posts the search to its booking service (`/booking/hotel`), which answers with the Booking.com address for a new window; that service cannot be called from here, so a valid search opens the live page (the Live page row, else the same path on www.lufthansa.com) in a new tab; nothing is sent.

Passengers: `Passenger picker | yes` turns the traveller line into a picker (adults without a hint, as www shows them on every brand, `Adults hint | 12+` adds one; children 2-11, infants under 2, the cabins of `Cabins | E, P, B, F`; default all four); `Airports | VRN, MUC` limits the origin and destination suggestions to those codes. `Group booking | [Booking from 10 persons](/it/en/book-and-prepare/group-travel-and-charter)` (a link) puts a link under the passengers in the picker, as ITA's and lufthansa.com's ("Booking from 10 persons" to the group travel page); it needs the Passenger picker row (without the picker there is no panel to hold it).

The group brands' travellers window (`travellers-dialog.js`, `travellers-dialog.css`): on a brand whose `scripts/brands.js` entry sets `travellersDialog` (Brussels, SWISS, Austrian, as their www's flight manager) and in a language with the window's texts (en, fr, de; the others keep the dropdown), the Passenger picker row's line opens a modal dialog instead: the "Travel details" tab, the travel class, the adults, children and infants steppers, the Group booking link, "Alternative fare selection" (best price, coupon, high) and the access code (optional, with www's hint), and Continue (Austrian: Save). Continue applies the window's values; the close button, Escape or a click beside the window leave the search as it was. The hand-off is the dropdown's, plus `universalCode` (www's form field `flightQuery.universalCode`) after the cabin and fare preference when an access code is filled. Texts: www's per language, a brand's own wording in its `travellersDialog.labels`, authored rows of the same names win (`Children hint`, `Infants label`, `Continue label`, `Access code hint`...). The "Redeem miles" tab (`travellers-miles.js`, Brussels and SWISS: the brand config's `travellersDialog.redeemMiles`): a second tab as www's (capture redeem-miles-001): the headline, Cash & Miles (three points, "Continue with login" to the replica's login page, a note, "Become a member" to the brand's Miles & More enrolment) and Book Award Flights (three points, "Search award flights" to miles-and-more.com, a note), in en, fr and de; no fields and no Continue under it. Tabs as tabs: the open one in the Tab order, the arrow keys, Home and End move between them; the window opens on Travel details. Austrian's window has its one tab (its Redeem miles tab not captured opened). A brand's look: its theme's `--travellers-dialog-*` tokens (travellers-dialog.css).

lufthansa.com's picker options (`picker-options.js`, each needs the Passenger picker row; none without its row):
- `Young adults | GB`: www's "Young Adults (12-15 years)" stepper after the adults, on the roots of the listed countries (`yes`: everywhere); they take seats like the adults and children (nine in all) and are handed off as `B15` after the adults. Texts: `Young adults label`, `Young adults hint`.
- `Fare preference | yes`: www's "Alternative fare selection" in the panel: best price (chosen, sends nothing), `COUPON` (change the sequence of the flights) or `HIGH` (flexibility, highest booking class), handed off as `farePreference` after the cabin; the traveller line then adds "Your fare selection is active.". Texts: `Fare label`, `Fare question`, `Fare default label`, `Fare coupon label`, `Fare high label`, `Fare applied`.
- A hint row left empty, or with its key cell only (`Adults hint`, `Young adults hint`, `Children hint`, `Infants hint`): no hint under that passenger type (the adults have none by default).

Hotel tab hand-off (scripts/handoff.js, brief 207): on the airline's own www host the search posts `/service/secured/api/core/booking/hotel` with X-Portal, X-Portal-Site, X-Portal-Language and JSON `{"cityName","checkInDate","checkOutDate"}` (the dates as midnight UTC, `2026-12-01T00:00:00.000Z`, as www) and opens the answer's target as www does (a form with a field per value, GET when `methodGet`, a new window when `newWindow`); a failure shows `Hotel handoff error` under the button. Every other host opens the live page in a new tab as before; `?handoff=post` on turnsthe.page and aem.page for a test.

## Supported variations

- `standalone`: the flight manager outside the homepage stage (`.flm-standalone`: flight search, stopover, cash-and-miles, hotel offers): a white card with a shadow and the tab bar, the form 20px inside.
