How each batch is swept
-----------------------
- A batch's documents: the READY rows of tools/reports/parity-2026-11-09/delta-so60-switch-NN.txt less the documents
  that live still has marked. The import helper's state commits on main ("so60 switch batch NN: n documents
  collapsed", "so60 batch NNh: n held documents cleared") give counts only, no paths. So tools/importer/
  switch-census.mjs --batch <list> --env live (our main--lh-com--moved-permanently.aem.live, 3 requests at a time)
  names them: a document with markers on live is held or skipped and not swept. The census also says when a batch is on
  live: all its documents read with 0 markers but the held ones.
- Host lufthansa.turnsthe.page, widths 1440 x 900 and 390 x 844, at most 3 pages at once, order 79's settle (load, lazy
  pictures eager, one scroll, network idle, every section and block loaded, pictures complete, 3 equal heights).
  so80/nb80.mjs runs order 76's checks and so78's text-collision probe (p-hit.js) in the same load: broken pictures,
  sideways scroll, never-loaded sections and blocks, overlaps, out of block, text spill or cut, empty sections and
  cells, heading and list sizes, text drawn under another element. Requests to www.*, lh-proxy and the airline hosts
  are refused and counted, never sent.
- Each page against its source-language copy (de/en for English, de/de for German, xx/<ll>; xx/en and xx/de against
  de/en and de/de): more than 15 % off at either width is a finding. A source not rendered yet tonight is rendered in
  the same run (its state that minute: switched or still marked).
- Each page against its own marked copy as rendered before its batch, where one exists: the only pre-batch renders of
  lufthansa.com documents on disk are order 78's (19 Nov, 20:36 to 21:23 CET). Of batches 07 to 16 they hold
  /xx/fr/faq-data-security and /xx/fr/faq-password-security (batch 14) and /xx/fr/support/support (batch 15).
  Everywhere else there is no "before" to compare, and the part says so.
- Kinds: FAULT = drawn wrong. PROPOSED = a rule for ema-adobe, gated with the rule injected in the same load. ROW = a
  source fix in delta-so80-com-faults.txt. LISTED = not proven, or fewer than 3 documents with no row. CONTENT = the
  document's own. DESIGN = drawn so on purpose (www's, or a documented rule). FUNCTION = an app or live answer that the
  refused hosts withhold. ARTEFACT = the check, not the page.
- Scratch (not in git): migration-work/parity-588/so80 (mk80.py, nb80.mjs, sum80.py, census.sh, the probes, outputs).

---------------------------------------------------------------
- Cause: styles.css's last-section pull-up after a grey band (body.brand-lufthansa main > .section.grey +

  768 px that section is out of the flow (subpage-nav.css: position absolute, top var(--subpage-nav-top)), so the -48
  px moves the nav 48 px above the place the block computes (20 px above the first element after the page title).
  Measured at 1440: /gb/en/mobility-partner-program-healthcare's nav section top 207 where the block set 255 (main 122
  + 133), the title 182-235. /de/en/upgrade-info (its nav after a non-grey section) is 255 where set.
- Rule (from 768 px, after that rule in styles.css; :is() keeps it above the pull-up's weight, 0,8,2 against 0,7,3):
    @media (width >= 768px) {
      body.brand-lufthansa main > .section.grey + .section.subpage-nav-container:last-child:is(.subpage-nav-container, :has(> .subpage-nav-wrapper > .subpage-nav)) {
        margin-top: 0;
      }
    }

  gb/en mobility-partner-program-healthcare, tiere-als-uebergepaeck, upgrade-business-class-long-haul,
